# 注册与游客访问

此功能保持升级后的原有边界：注册默认需要注册邀请码，游客默认关闭。
修改界面设置不会自动创建外部账号、平台凭据或修改部署安全配置。

## 允许自行注册

管理员在「实例设置」选择注册模式：

- **关闭**：不接受新用户注册
- **仅邀请码**（默认）：需要有效、未使用的注册邀请码
- **开放注册**：用户自行填写账号、密码和可选昵称，不需要注册邀请码

已注册账号仍使用原来的登录方式。开放注册也受既有账号验证、请求频率和密码散列并发限制。
注册模式的改变由服务端检查，隐藏注册按钮不是权限边界。

## 允许游客进入一个房间

1. 管理员在「实例设置」开启「游客模式」
2. 房主或管理员进入房间管理，打开「游客访问」，保存允许游客进入
3. 生成此房间的**观看者**邀请，将完整邀请交给对方
4. 对方在登录页选择游客入口，粘贴邀请并填写可选昵称

两层开关缺一不可。游客还必须持有有效的房间邀请；房间编号本身不能进入。
定向邀请、Moderator 邀请、过期或撤销的邀请不能用于游客入口。
正常邀请的使用次数上限和房间人数上限仍然生效。

## 游客可以做什么

- 进入获准的这一个房间，查看房间成员并聊天
- 观看房间当前选中的影片，通过现有媒体播放接口请求自己的播放会话
- 查看当前影片必要的房间内资料

游客不能创建房间、进入其他房间、控制播放、编辑待播列表、管理片源、
浏览媒体库、修改账号资料、绑定平台账号或参与 P2P / 分布式计算管理。
房主也不能把游客转为房主、控制者或 Moderator。
私人库影片只有在当前房间得到有效的「所有房间成员」分享时才能观看；
「媒体库成员」分享不会扩大给游客，私人库目录始终不可浏览。

## 到期、退出与撤销

- 每次游客身份最多有效 **2 小时**，不续期、不转为注册账号
- 浏览器使用不向脚本暴露的会话 Cookie，写操作检查同源和 CSRF
- 关闭实例游客模式、关闭房间游客访问、关闭房间、移出成员或退出登录，都会撤销当前游客权限
- 重新开启开关不会恢复旧游客会话
- 撤销邀请会阻止后续进入；终止已经进入的游客时，请移出成员或关闭游客访问
- 已到期或撤销的浏览器会话，可在登录页明确退出旧游客会话，再使用新邀请进入或正常登录

HTTP、WebSocket 和不携带登录 Cookie 的媒体签名请求都检查当前权限。
已经发送到网络缓冲区的字节无法收回；撤销后不再授权新的消息或媒体读取。
到期清理按有界批次执行，保留共享历史所需的不可登录匿名身份引用。

## 回归验证

- `node tests/scoped-guests-migration.mjs`：独立 PostgreSQL 上的迁移、默认值、权限与撤销边界
- `node tests/scoped-guests.mjs`：独立 Server/Worker/PostgreSQL、真实生成媒体、HTTP、WebSocket 与媒体字节
- `npx vitest run tests/guest-room-controls.test.ts`：房间游客设置的真实组件状态与中断流程

集成测试需要按现有测试说明设置 `RAINSYNC_ARTIFACT_DIR`、`CARGO_TARGET_DIR`
以及 PostgreSQL / FFmpeg 环境；必须使用当前源码构建的 Server、Worker 和 fixture example。
不要将这些测试指向已有部署或生产数据库。
