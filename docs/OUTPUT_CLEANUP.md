# 旧执行代次的独立回收

迁移 `0017_obsolete_output_cleanup.sql` 为读取租约增加可空的 attempt，并为产物增加清理者、租期和下次检查时间。升级先停止旧 Worker，再迁移和启动新版；旧 Worker 不识别代次读取准入，不能混跑。历史空 attempt 租约在到期前保守保护整个任务目录。

生成媒体的 HTTP 读取在打开文件前，锁定 cache_entries 行，核对任务当前 attempt、可读状态和有效播放会话，再登记对应代次的读租约。任务切到新代次后，已取得租约的旧响应可以继续排空；它的租约仍保护旧文件。新请求无法通过旧快照取得旧代次租约。整目录淘汰继续检查所有读取租约。

Worker 独立维护循环每五秒最多检查 32 个到期候选。只清理 `attempt > 0`、严格小于任务当前 attempt 且状态为 abandoned/failed 的目录；当前 writing/published 产物不受此路径影响。领取清理与读取准入锁同一 cache_entries 行，旧代次读者或未绑定代次的读者会阻止领取，当前代次读者不会。清理者租期三十秒，更新完成须匹配清理者和有效租期。数据库操作各有三秒截止，文件删除在事务外执行。

物理路径仅由配置缓存根、UUID 和正整数 attempt 构造，不使用数据库 relative_dir。删除前验证规范化路径边界，并拒绝任务目录或代次目录是符号链接。attempt 0 的历史布局使用任务根目录，仍由整目录淘汰处理，不能按代次删除。文件系统访问错误保留记录等待重试；清理循环停止时等待已启动的文件操作完成，不遗留脱离生命周期的删除任务。

清理不删除产物证明记录。每次领取或完成至少间隔六十秒后再次检查，因此失联旧 Worker 恢复并重新写出的私有文件仍能再次回收。租约过期无法证明旧操作系统进程已停止；这里保证旧文件不成为当前产物，并最终重复清理，不承诺暂停中的进程立即消失。直接子进程的恢复后回收由执行监督器负责，后代进程组及不可中断磁盘操作仍是独立验收项。

验证入口：`verify_output_cleanup` 隔离 PostgreSQL 示例、`tests/output-cleanup.mjs` 的实际 Worker 循环、`tests/worker-processes.mjs` 的真实 FFmpeg 旧 Worker 暂停/换代场景。前两者分别覆盖锁和租约竞争、活动会话下物理回收及晚写文件复查；真实 FFmpeg 矩阵另检查旧进程回收、新代次文件保持不变及旧目录删除。不同 Worker 仍必须共享同一缓存卷。
