# 账户注销

个人资料页的“注销账号”先读取 `GET /api/v1/users/me/deletion`，列出仍归当前账号所有的房间和私人媒体库。先通过房间成员界面、私人媒体库界面转移所有权，再刷新检查。关闭或归档的房间也须明确安排继任者。房间转移不转移媒体库，媒体库转移也不授予房间角色。

唯一管理员必须先安排另一名管理员。`POST /api/v1/users/me/deletion` 要求有效登录、同源请求、CSRF、当前密码及 `confirmation: "DELETE"`。错误密码每账号最多五次/十分钟。后端在事务锁内重新检查所有权、管理员和精确会话，预检结果不能替代最终验证。

提交成功后：

- 全部设备登录会话、房间成员关系、控制凭证、P2P 信令身份、个人权限和发出的授权被撤销。
- 自己的播放会话停止，媒体任务取消，NAS 计算失去授权；其他成员的播放不受账户注销的会话清理影响。若他人的播放依赖该账号发出的私人库共享授权，该授权会撤销，需由新所有者重新授权。
- 平台凭据和自动续期材料被清除，待处理平台登录失效；在途续期不能恢复旧凭据。
- 原登录名替换为不可注册的匿名标识，密码不可用，头像和个人改名清除。共享聊天、房间状态、他人的资源及必要审计外键保留，显示名称为“已注销用户”。注销不会删除他人在消息正文中写下的文字，也不删除第三方平台账号。

迁移 `0081_account_exit.sql` 保留匿名主体行，并通过数据库准入触发器禁止旧组件给已注销主体重新创建登录、所有权或权限。`users`、`sessions` 的原列形状保持兼容；注销后不能恢复原主体。当前登录名释放，可重新注册为全新主体，旧记录不会因此重新归属。

控制集群中，账号墓碑及全部登录的撤销在一个事务中提交，权限和邀请查询立即排除已注销的成员、授权者及指定受邀者。房间成员、邀请和委派权限的物理清理由持久队列交给该房间的控制节点处理，仍执行原租约及提交围栏。节点失联时队列保留并重试；房间列表可能短暂保留匿名成员，不能因此恢复登录、媒体访问或授权。单实例在注销事务内完成对应清理。缺少创建者绑定的历史房间邀请无法推断实际创建账号，应由现任房主在邀请列表中撤销。

请求结果未知时先重新检查登录状态。已注销账号的后续请求会返回会话失效，不能以新登录复用旧主体的注销请求。自动回归：`node tests/account-exit.mjs` 使用独立 PostgreSQL 和真实 Server，覆盖迁移前置条件、其他成员数据保留、注销后重启和旧写入拒绝。
