# 播放入口就绪状态

`GET /api/v1/playback-sessions/{id}` 返回生成契约 `PlaybackReadiness`：

```json
{"session_id":"会话 UUID","status":"preparing","complete":false,"available_until_ms":4000}
```

`queued` 表示任务排队；`preparing` 表示当前执行代次还没有发布首段；`ready` 表示可以开始加载入口。`complete` 表示本地生成任务已完成；无需本地生成的直放或上游地址立即返回 ready/true，这不保证上游服务或网络持续可用。

读取必须通过登录认证，并匹配会话所有者、有效期、未停止状态、当前房间影片代次及成员资格。不存在或不可访问的会话统一返回 `INVALID_PLAYBACK_SESSION`，不泄露其他用户的任务状态。查询在同一条 SQL 的快照中完成，只关联当前 attempt 的产物；失败及取消使用现有结构化错误，原始任务错误不会进入响应。

校验版本 2/3 的产物必须具有已发布的清单及至少一个分片才 ready。版本 3 的发布还经过首段实际解码。旧版本产物保留 Worker 按请求校验的兼容路径，ready 不替代分片读取时的校验。

网页对需要本地生成的方案每秒查询一次，最多等待 180 秒。期间保留原请求编号和会话，不重新 POST 播放准备。三次连续传输或临时服务错误后结束等待；外部取消保持静默，失败或等待超时复用既有按 key 撤销逻辑。网页仅在 ready 后绑定媒体地址。状态接口应与网页一起发布；旧 Server 尚无此接口时，新网页的本地生成路径不能正常等待。

`available_until_ms` 是已提交清单中 EXTINF 之和，区间为相对方案 `timeline_origin_ms` 的 `[0, available_until_ms)`。新代次没有可见清单时为 0，直放/上游或旧校验版本没有测量值时为 null。可选查询参数 `relative_position_ms` 必须有限且非负；生成任务尚未完成时，目标恰好等于或超出区间末端返回 preparing，即使首段早已发布。默认查询目标为 0。已完成任务不会为永远不会出现的位置继续返回 preparing，网页会使用已生成终点限制本地目标。

网页首次等待以最新房间时间减去方案时间原点查询，播放中的自然追赶也复用原会话等待区间生成，就绪后从当前房间位置重新加载入口。等待期间取消纠偏 seek；取消、换片、重新加载和错误恢复使旧等待失效。显式的远距离 seek 仍重新准备方案。一次等待最长 180 秒，终态失败不会每个 tick 重新启动轮询。

这个区间描述清单已发布的时间范围，不保证浏览器已经下载、解码或缓冲该范围。范围来自已提交快照，文件读取仍须通过原有摘要和权限校验；目前不承诺任意设备上的无缝尾部恢复。旧版本、真实 Safari、慢编码持续追赶及不同时间戳偏移样本还需扩展实测，W05/W06 的完整验收保持未完成。

验证包括隔离数据库的直放、归属、停止、当前代次/首段快照、终态错误检查；前端等待、超时、取消、错误会话响应和撤销测试；浏览器确认准备中不绑定地址、就绪后只加载原会话。数据库测试使用受控产物，不代替实际 FFmpeg 和设备兼容验证。

在途取消另外通过浏览器验证：换房或收到区间外 SEEK 时旧 GET 确实被中止；其迟到 ready 响应不能覆盖新方案，不产生未处理异常或额外准备。主动 SEEK 仍按新的房间位置请求方案。

## 慢编码与原生恢复

原生 HLS 的 `seekable` 可能暂时为空，但 `buffered` 已有可用数据；播放器在这种情况下使用缓冲区间判断能否恢复，避免等待 `seekable` 的同时始终不调用 play。自然播放超出当前可用区间仍等待原会话生成，不额外准备。

原生 HLS 报解码或格式错误（媒体错误 3/4）且设备支持 hls.js/MSE 时，只切换一次到 MSE，继续使用同一授权入口和最新房间时间。切换会取消旧区间等待。网络错误保留原生有限重取逻辑，MSE 再次失败不会切回原生形成循环。此处仅处理传输实现差异，不代表所有编解码组合均可降级。

真实慢编码入口为 `node tests/slow-playback.mjs`，依赖已构建的 `rainsync-worker-validation:local`（可用 WORKER_TEST_IMAGE 指定）、Docker、Playwright Chromium。它创建隔离 PostgreSQL、Server、Worker 和 Vite，FFmpeg 真实编码 40 秒样本，仅对编码输入施加 0.5 倍读取速度；首段解码检查不被限速。浏览器 API、清单和分片请求均经过真实服务，无响应桩。分别检查 MSE 和先选择原生的路径，报告明确记录最后使用的传输；Chromium 原生路径失败后回退成功不能当作 Safari 验收。

测试从暂停房间开始，实际解码播放到追上生成边界，再暂停房间让编码追到固定目标，最后恢复播放并检查新解码帧、同一会话和 attempt。固定 0.5 倍生成速度不能追上始终 1 倍前进的房间；本测试没有声称可以克服这个速度差，也不替代长时间持续运行、不同时间戳和真实移动设备测试。
