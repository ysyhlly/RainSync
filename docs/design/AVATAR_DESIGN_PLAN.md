# RainSync 头像设置：设计与实施计划

日期：2026-09-28。仅设计，尚未实现。补充 ACCOUNT_REGISTRATION_DESIGN.md / ACCOUNT_REGISTRATION_PLAN.md。

## 用户已确认与复用边界

- 用户可以设置头像；长方形原图可以调整取景，最终文件固定 512×512。
- 首版只支持静态 JPG/JPEG、PNG、WebP，不支持 GIF、SVG 或其他动态图片。
- GitHub 项目只作为交互及实现思路参考，不复制、移植其源码，不直接安装/嵌入它们的裁剪、上传组件，也不复制其界面素材。
- 本项目独立编写裁剪坐标、鼠标/触摸交互、预览、导出和上传逻辑，使用浏览器标准 API；保持已有 Vue/TypeScript 和服务端技术栈。
- 仍只更新“杂项”的设计工作包并本地提交；没有修改 RainSync、安装组件或创建真实用户头像。

这里的“不直接复用”针对所参考的头像裁剪/上传项目。浏览器内建能力和 RainSync 已有 Vue、Rust、FFmpeg 等基础运行环境继续使用；不因为参考项目采用了某个库就把它拉进依赖。

## 页面与流程

注册表单仍保持登录账号、可选昵称、密码、确认密码；头像在登录后的“个人资料”中设置，不把上传失败混入开户事务。初始头像采用昵称或登录账号首个可显示字符的圆形占位。

个人资料页增加头像区：当前头像、“上传头像”（有头像时“更换头像”）、“恢复默认”。昵称保存与头像保存是独立操作；修改一个不提交另一个未保存的草稿。没有头像时不显示无意义的恢复按钮。

选择文件 → 检查格式与大小 → 本地加载 → 打开“调整头像” → 拖动/缩放取景 → 预览 → “保存头像” → 服务端确认 → 更新本人侧栏、资料和后续聊天展示。

### 裁剪弹窗

- 米色面板；桌面左侧裁剪、右侧圆形大小预览，底部缩放滑块、加减、重置、取消和保存。移动改为裁剪区在上、预览和操作在下。
- 固定正方形取景，不提供自由比例；保存方形图片，圆形只用于 UI 遮罩，不把圆外像素强制擦掉。
- 长图/宽图默认居中取景，用户拖动原图和放大调整；不拉伸长方形到正方形。取景区域始终被图片覆盖，不留下无意空白。
- 同时支持鼠标拖动、触摸拖动、双指缩放，以及可键盘操作的缩放控件；拖动区内阻止页面滚动，区外仍可正常滚动。
- 正常预览约128px，小预览约40px；输出明确标示“512 × 512”。文字提示“拖动图片并缩放，调整头像显示范围”。
- 小于512px的图可以继续，提示“原图较小，保存后可能模糊”；保持512×512输出，不冒充增强清晰度。
- 取消/关闭丢弃本地草稿，不上传、不更改当前头像；保存期间禁用重复提交。上传失败保留本次裁剪便于重试，旧头像继续显示。
- 恢复默认需明确确认，只清除头像，不清除昵称、不改变登录账号。

### 主题和播放

沿用 #E5D1C1 / #9E7867；主按钮使用深色字。头像图像保留原色，透明图像保留透明度，周围背景使用语义颜色以便将来深色模式。裁剪区遮罩采用低对比暖色，避免整个界面变成深色编辑器。

头像储存比例1:1属于账号资料；媒体库、待播和迷你播放器的影片图像仍严格16:9。进入资料页、选择文件、裁剪和保存过程中不停止播放，不创建新的 video/WS/播放会话。小屏弹窗可盖住迷你画面，底层音视频实例继续运行。

弹窗约220–280ms淡入/轻位移，拖动和缩放即时响应，不给指针移动叠加缓动。reduced-motion去掉位移；打开聚焦标题/首控件，Esc取消，关闭还原触发按钮焦点。

## 文件处理与上传设计

建议原图限制：不超过10MiB、总像素不超过4000万且任一边不超过16384px；超限提示用户换图。文件扩展名只作选择辅助，要检查实际签名、尺寸与可解码性。PNG/APNG、WebP的动画变体不作为静态头像接受，不默默截第一帧。

浏览器本地完成朝向校正和取景，用原图像素坐标保存裁剪状态。渲染到尺寸明确为512×512的Canvas，再导出PNG Blob作为上传中间格式，避免前后端连续多次有损压缩。原始大图不上传、不存数据库、不进入日志。使用本地 ImageBitmap/Canvas 预览，释放位图和事件监听；无需将 blob URL 加入现有 img-src CSP。

独立裁剪模型：朝向校正后尺寸W×H，缩放z>=1，源正方形边长L=min(W,H)/z；中心(cx,cy)分别限制在[L/2,W-L/2]及[L/2,H-L/2]。可见取景宽度V时，拖动dx像素对应源中心位移-dx×L/V；纵向同理。缩放默认保持取景中心，双指同时平移按中心移动处理。导出以(cx-L/2,cy-L/2,L,L)作为source rect，等比例映射到512×512。这些关系从本项目固定方形需求推导，不移植参考仓库代码。

独立验收样例：1600×900图在z=1时初始取景(350,0,900,900)，z=2中心不变时为(575,225,450,450)；900×1600图初始为(0,350,900,900)。浏览器的CSS尺寸和设备像素比都不能改变上述原图取景结果。

服务端只接收512×512静态PNG中间图，单次请求上限建议2MiB，重新解码确认内容，不相信客户端声称的尺寸。用现有FFmpeg运行环境重新编码为单帧WebP，目标不超过256KiB，默认有损质量约82，可在不改变512分辨率的前提下适度降低质量；保留alpha，去掉EXIF、GPS及其他原始元信息。达不到边界时返回明确错误，旧头像不变。

FFmpeg只通过参数数组与内存管道处理本次图片，不拼shell、不接收用户URL/路径、不开放网络输入；设置解码/编码时间、进程并发和输出字节上限，取消/超时必须回收子进程。上传前先校验登录、CSRF、Origin、body大小、PNG头/尺寸及静态特征，再做有界解码。未来实施先确认现有构建带有WebP编码能力和alpha支持；未确认之前不能宣称功能可用。参考既有基础工具的[编码接口文档](https://ffmpeg.org/ffmpeg-codecs.html#libwebp)，不是复制其他头像项目的实现。

## 存储与接口提案

建议首版把最终小图存入独立 user_avatars 表（PostgreSQL bytea），每用户一条当前记录：user_id、version、content_type、content、updated_at；数据库约束限制最终体积，512×512由解码结果验证。恢复默认后保留新的version记录，content/content_type置null，而非删掉整行，以免旧上传误把“删除后无头像”当成“从未设置过”而覆盖。头像URL/版本与数据分离查询，不把二进制带进me/聊天JSON。

选择理由：当前Server容器没有独立的可写头像持久卷；小尺寸单头像用现有数据库即可与账号一起备份，替换/恢复可原子提交，不需要新增图床、对象存储账号或部署服务。将来用户规模显著增大再独立迁移存储，不把它混入本轮。

头像与 user_profiles 分表：恢复默认头像不删除昵称；清空昵称也不删除头像。现有users/sessions表形状保持不变。

| 拟定接口 | 权限/输入 | 结果 |
|---|---|---|
| PUT /api/v1/users/me/avatar | 本人Cookie、CSRF、Origin；image/png Blob、操作UUID、预期旧版本 | 重新验证编码并原子替换；返回avatar_url、avatar_version；不修改昵称 |
| DELETE /api/v1/users/me/avatar | 本人Cookie、CSRF、Origin；操作UUID、预期旧版本 | 恢复默认，avatar_url为null，保留新avatar_version；重复同操作幂等 |
| GET /api/v1/users/{id}/avatar?v={version} | 已登录 | 当前指定版本WebP；无权限/不存在/版本过期按契约返回；不提供原图 |

扩展 /auth/me、个人资料GET/PATCH、聊天历史和CHAT消息的 avatar_url、avatar_version（可为null）；普通资料PATCH仍只写昵称，不能注入任意avatar_url。图像失败时显示默认占位。当前聊天消息有稳定user_id，头像不参与权限识别。

图片请求先认证再处理ETag；使用private、no-cache和nosniff，Content-Type固定服务端实际编码结果。URL带版本避免保存后还显示旧图；不给匿名页面展示用户头像。首版其他客户端通过新消息/重新加载获得更新，不新增全站头像变更广播。

新上传完成前保留旧头像；成功后才替换。使用预期版本作条件更新，避免两个标签页或旧请求晚完成覆盖新图；重复同一操作UUID不生成多次版本。响应丢失时先读当前资料确认版本，不把未知结果当成失败直接覆盖；冲突提示刷新后再保存。删除和上传并发也须遵守版本条件。
必须测试“最初无头像的上传A挂起→上传B成功→恢复默认→A才完成”：A不得重新激活头像，恢复默认保留的版本记录负责拒绝它。默认占位只看avatar_url是否为空，不把非空version误认为有图片。

当前Server全局body上限64KiB不足以承载中间图，未来仅放宽头像上传路由到2MiB，其他API维持原限制。增加每账号上传频率和全站编码并发限制；不能把一次头像处理拖成媒体播放任务或占用其队列。
