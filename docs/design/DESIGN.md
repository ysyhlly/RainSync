## 2. 视觉方案选择

考虑过三个方向：
1. 温暖私人影院：米色底、自然影像、暖棕强调、清晰功能布局。推荐，符合一起观影的使用场景。
2. 电影杂志：大字号、强烈不对称、巨幅封面。适合宣传页，但挤占播放与聊天空间。
3. 极简管理工具：紧凑列表、近乎无装饰。适合管理区，观看区的电影感偏弱。

采用方案 1；管理区在同一套颜色、字体和控件下提高信息密度。现有深色外观、渐变文字封面、英文装饰标语、全站大组件全部退出最终版本。保留 RainSync 名称，纯文字呈现，不加品牌图标。媒体库/观影/片源管理沿用三张 v2 图；账号采用 v4 注册图、v3 邀请码管理图、v5 头像资料图；本规范及专项文档优先于图片细节。

前端设计技能只借用配色、排版、层次和反馈原则；不把营销页的大标题、滚动故事或 React 默认栈套到实时观影和管理界面。

桌面左侧约 208–224px 导航；主区域自适应，内容最大宽度约 1600px，侧边距 24–44px。不是所有页面都堆在同一长页。

### 登录与房间列表

登录页保留纯文字品牌名与简洁登录表单，增加“使用邀请码注册”。注册页采用同一色板的居中面板：桌面左侧窄步骤区、右侧表单，手机为顶部步骤和单列表单。认证恢复时显示骨架，不能先短暂闪出登录表单。具体字段、状态、流程及动效以账号专项规范为准。

注册分“验证邀请码”和“设置账号”。第二步依次显示不可变的登录账号、可选昵称、密码和确认密码。验证邀请码不会消耗或预留；最终注册成功后才消费，建立普通账号并自动登录到 /rooms。无房间时使用真实空态，不替用户自动加入群组。注册邀请码和原有房间邀请相互独立。

日常用户区和聊天显示昵称及头像，个人资料页可分别修改昵称和头像，登录账号不可编辑。头像选择后打开独立裁剪弹窗，固定1:1取景、输出512×512、圆形显示；原图不上传，确认保存后才更换。账号规则和现有账号兼容性见 ACCOUNT_REGISTRATION_DESIGN.md，头像实现见 AVATAR_DESIGN_PLAN.md，显示资料不作为权限依据。头像不属于媒体封面，影片图像仍统一16:9。

房间列表只显示接口实际提供的房间名称等信息，不捏造在线人数、成员头像或正在播放影片。创建使用有名称输入的抽屉。加入邀请支持粘贴旧 JSON 邀请并自动拆出房间 ID、token，也保留两个独立输入；不把邀请 token 写进 URL、日志或分析事件。

### 媒体库

影片网格桌面随宽度 3–4 列，移动 2 列，所有封面使用 aspect-ratio: 16 / 9。标题、来源类型、时长放在图像外的下方，卡片整体无需是 16:9。具体操作在键盘聚焦、悬停和触屏上都能找到。

搜索 250ms 防抖，回车可立即提交；新查询重置游标。上一页/下一页来自游标，不把当前页数量当总数。区分首次加载、搜索中、无搜索结果、空媒体库和加载失败。

点击影片：当前房间有控制权则可切片；没有房间则先选择/创建；观看者可查看信息，但不显示可成功控制房间的假按钮。添加待播与播放是两个清晰动作。

正在播放的标题由按 media_id 缓存的影片元信息提供，不从当前搜索页临时查找。深链进入且没有元信息时显示“正在播放”，不误报“请选择影片”。

### 观影房间

桌面播放器与聊天约 3:1 分栏，播放器内画面 16:9，下方米色控制栏固定可见，不把浅色图标直接叠在亮视频上。字幕仍由真正的 video track 渲染；字幕可读性独立于应用浅色主题。

主要控件：播放/暂停、时间与进度、音量、倍速、全屏。次级选项：音轨、字幕、播放方式、重新加载。一般用户看到“自动”，直放/转封装/转码放进高级选项，不主导日常流程。

控制权提示清楚：只有房间控制者或管理员可以发房间播放、seek、倍速、切片命令；音量、音轨、字幕是本机偏好。失去控制权只禁用房间操作，不停止聊天和观看。

邀请抽屉展示可复制的完整邀请信息和有效期；只在本次已生成的邀请上提供撤销入口，不伪造历史邀请列表。控制者/所有者的按钮展示以实际后端规则为准，失败反馈就地保留。

待播列表排在播放器下方；聊天自动滚到新消息仅当用户本来在底部，否则显示“有新消息”，不抢阅读位置。发送中、失败、重试使用稳定消息编号，不依靠清空输入制造假成功。

### 迷你播放器

登录后的应用外壳持有唯一 video 元素、HLS 实例、播放方案和房间连接。普通路由变化只切换展示尺寸和布局。不要通过两个 video 元素、动态 key、卸载再挂载或重新 POST 播放会话制造“无缝”的假象。

桌面固定在主区域底部，不覆盖左侧用户区；缩略视频、标题/房间、控制者的播放按钮、进度、音量和“返回房间”。为页面正文、弹窗和输入保留实际底部高度。

移动固定在底部导航上方，约 64–76px；缩略视频、标题、返回、音量/静音，房间控制入口根据空间收纳。软键盘打开时表单输入和发送按钮始终可见，迷你播放器可暂时收起画面但不换实例。

房间真正切换、登出、登录失效、成员资格失效和应用销毁才触发对应清理；导航到管理区不清理。登出先尽力取消旧播放再退出，失败保留取消编号，不在前端假装服务端已清理成功。

### 管理区

片源列表显示名称、类型、操作。检测扫描采用行内忙碌和结果提示，没有百分比接口就不显示假进度；成功后的 count 只表示本次扫描结果，不当实时库存。

添加源抽屉随类型改变字段。本地填写容器路径；HTTP 填 URL 及可选请求头；Jellyfin/Emby 填 URL、User ID、访问令牌。凭据输入不会混入标题、错误日志或页面缓存。

NAS 页面显示 revoked/last_seen 的真实含义，不仅根据最后联系时间武断标成“在线”。配对码有复制反馈和本次生成后的十分钟倒计时，服务端有效期才是最终依据；撤销需清楚说明影响并确认。

“账号与注册”默认进入注册邀请码列表，次级标签保留手动创建。生成抽屉含数量（建议1–50，默认1）、有效期（1/7/30天，默认7）及备注；生成结果可单条/全部复制，完整邀请码仅当次显示。历史列表展示尾号、状态、有效期、使用者及撤销入口；没有完整邀请码再次查看按钮。

手动创建同步使用登录账号、可选昵称、密码。未来新建账号规则统一为至少8个ASCII可打印字符密码；目前代码仍是至少12字节，本轮没有改变它。原有账号登录不强制新规则。新增接口、存储、并发与错误语义由账号专项 Plan 承担，不能仅把表单画出来就认定功能完成。

## 5. 数据现实与效果图的差别

当前媒体接口只返回 id/title/duration_ms/kind，没有海报、简介、年份、评分、总数或观看历史。首版使用原创通用封面/无封面排版，不把随机风景宣称成影片真实海报；效果图中的六张摄影海报属于视觉示意。

真实逐片海报、电影元信息抓取、设备档案、成员在线人数、完整用户列表、片源编辑删除和高级管理仪表盘仍不在本次范围。注册邀请码及本人昵称资料是用户明确要求新增的后端扩展，已单独规划，不代表当前已有这些接口。

生成图里的头像、时长、聊天时间、NAS 信息和片名均是演示内容，不代表本机数据。品牌处只有 RainSync 文字；功能区图标在实现时统一。NAS“自动同步”是文字状态而非可点击按钮。生图可能有字形、按钮字色和缩略图比例误差，最终以本规范的功能文案、深色按钮字和精确 16:9 为准。不要将生成图整张切片当作应用实现。

## 6. 动效规范

| 场景 | 时长/方式 | 限制 |
|---|---|---|
| 按钮按下/悬停 | 120–160ms，背景/阴影/0.98 缩放 | 不改变周围布局，触屏无悬停依赖 |
| 导航选中 | 180ms，背景与指示条 | URL/业务状态立即变化 |
| 页面切换 | 220ms，opacity + translateY 8px | 不包住 PlaybackHost，不动画 video 的挂载 |
| 表单抽屉 | 280ms，translateX 24px + opacity | 打开后聚焦标题/首字段，Esc 关闭并还原焦点 |
| 主播放器与迷你切换 | 240ms，外围控件淡入/位移 | video 始终同一节点，尺寸切换不触发 reload |
| 媒体网格首次进入 | 220ms，每项错开 20ms，最多前 6 项 | 搜索、分页、大列表不逐项长时间排队 |
| 消息/短反馈 | 160ms，轻淡入 | 用户滚动历史时不自动定位 |
| 缓冲/重连 | 静态状态文字 + 轻量图标 | 不用循环呼吸整个播放器、不虚构百分比 |

默认缓动 cubic-bezier(0.22, 1, 0.36, 1)。不使用 transition: all。首版用 Vue Transition/TransitionGroup 和 CSS，不因“流畅”默认引入大型动画库。已有播放器纠偏计时与视觉动画相互独立。

prefers-reduced-motion: reduce 下关闭位移、缩放、错峰和装饰循环，只保留即时状态或 <=80ms 的透明度变化。用户偏好不得改变房间同步算法。可采用 Vue 内建过渡处理出入场，参考 [Vue Transition](https://vuejs.org/guide/built-ins/transition.html)；减少动态效果依据 [MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)。

## 7. 响应式与可访问性

- >=1280px：完整导航、3 列片库，宽屏可 4 列；播放器/聊天并排。
- 768–1279px：导航可折叠，2–3 列片库；空间不足时聊天移至播放器下方。
- <768px：顶栏品牌与房间入口；底部“放映室/媒体库/管理”（管理员可见）；片库 2 列，播放器全宽，聊天/待播用切换面板。
- 覆盖 360、390、768、1024、1440、1920 宽度；主要操作不横向溢出。
- 使用动态视口和安全区；聊天输入、迷你播放器、底栏高度有明确布局优先级。
- 所有输入有 label；错误就地展示并关联输入；全局故障有可关闭 alert 和诊断编号。
