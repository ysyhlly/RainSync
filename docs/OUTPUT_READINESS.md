# 本地 HLS 分片读取检查

以下描述版本 1 的兼容读取路径。迁移 0014 后的新产物使用 [持久化可见清单和分片摘要](OUTPUT_PUBLICATION.md)，不会在 HTTP 入口直接读取编码器的私有清单。

Worker 交付本地生成的 EVENT 清单前，检查完整清单语法、初始化段，以及此前尚未验证的连续编号分片。文件必须已使用最终名称落盘，初始化段包含非空 ftyp/moov，分片包含非空 moof/mdat，所有顶层 box 均在文件长度内。清单引用的新增分片仍缺失或截断时，运行任务短暂等待后返回可用性错误，不把这个快照作为成功响应。

进程内最多缓存 128 个 attempt 目录的已验证分片数和清单前缀摘要。后续清单只追加分片时复用前缀验证；清单缩短或前缀变化则重新检查。磁盘结构检查最多并发四个，运行在阻塞线程池；请求取消后，仍执行中的检查继续持有并发许可。该缓存是可丢弃的读取优化，没有替代数据库的 attempt、租约及最终 published 状态。

分片请求仅接受 init.mp4 和规范编号的 indexN.m4s，且分片必须已出现在当前完整清单中。临时文件、任意旁文件和未公布分片都不能直接读取。每次 GET、HEAD、Range 均重新检查该文件结构，使用同一个已检查并回到起点的文件句柄返回内容，避免检查后再打开时被重命名替换。已完成任务缺片立即失败；完成清单的摘要也在子资源请求中检查。

版本 1 的增量前缀按 FFmpeg 在独立 attempt 目录中将完成分片改为最终名称、之后不再修改的写入约定复用；已验证分片被外部进程删除或改写，由后续文件请求重新检查。该兼容路径没有逐分片内容哈希，不能识别保持 box 边界不变的载荷损坏。版本 2 已增加持久化发布和内容摘要，但同样不能防止持有卷写权限的外部进程在校验后原地改写同一文件。旧代次独立清理和长时间负载等仍是 W05 待办。

验证入口：

- `cargo test -p rainsync-media-worker --locked`：缺失/临时/截断分片、增长和重写的清单、规范文件名、已检查句柄的读取位置。
- `node tests/integration.mjs`：真实 Worker 路由拒绝临时/未公布/损坏文件；等待分片最终重命名；GET、HEAD、Range 无绕过。产物字节是结构测试夹具，不是可解码视频。
- `node tests/worker-processes.mjs`：独立镜像中生成真实 FFmpeg HLS；编码尚未结束时读取分片，完成后通过 Worker HTTP 入口完整解码，并验证 HEAD/Range。其余进程与缓存故障矩阵同时保留。
