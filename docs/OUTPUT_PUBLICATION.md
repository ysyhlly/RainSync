# 可见 HLS 清单与分片内容证明

迁移 `0014_output_snapshots.sql` 将新领取产物的 validation_version 设为 2。旧产物保留原版本，不能在没有内容证明时回填为新版。升级时仍须停掉旧 Worker，再迁移并启动新版；不支持混跑。

迁移 `0015_first_segment_decode.sql` 将此后的新产物设为版本 3：在版本 2 的完整性检查上增加首段实际解码。旧版本 2 保留原版本，只表示通过了摘要检查；不会被自动追认为已通过首段解码。

FFmpeg 继续在每个 attempt 的私有目录中写清单及临时分片，完成分片使用最终名称。Worker 的发布任务与续租、容量检查并行运行：读取完整清单，只对新出现的初始化段/分片做结构检查和 SHA-256 计算。文件哈希使用 64 KiB 缓冲，并限制读取到初始长度加一字节；长度或修改时间变化会拒绝这次证明。失败或仍在写入的快照不会覆盖此前的可见版本。

校验结束后才开启数据库短事务，锁住当前任务与产物，核对 owner、attempt、running 状态、未过期租约及有效会话。事务同时写入分片编号、长度、摘要，并替换 media_outputs.visible_manifest。分片证明不可被另一个摘要覆盖，重复同一证明允许幂等重试；缺失初始化段或任一连续编号分片则回滚。提交前再检查一次租约，避免在等待锁时已经失去执行权。

版本 2 及以后的 HTTP 入口只读取数据库中已提交的清单文本，不直接读取 FFmpeg 正在重写的 index.m3u8。数据库事务替换的是整个可见清单，因此读者只能看见前一版或后一版，不存在半份新清单。清单和证明以相同 job/attempt 绑定；请求旧代次仍返回 STALE_MEDIA。

版本 3 在首次提交前把已核对摘要的初始化段和首个分片通过管道交给 FFmpeg。仅允许 pipe 输入协议、限制解码线程，启用严格错误退出，必须成功完成且至少输出一帧校验记录；只有头部或零帧不能作为解码成功。检查覆盖完整首段，不启动额外的网络读取。检查最长十秒，输出逐行解析，总量限制 2 MiB、单行限制 4 KiB；通过后仅在本 attempt 内复用结果。

无法解码会停止编码并使任务失败；检查超时保留可恢复的执行租约，等待队列换代次重试。取消检查 future 不丢失子进程所有权，任务收尾显式 kill/wait 后才释放写入预算或退出。快速编码可能在后台检查结束前退出，最终发布路径仍须通过同一检查，不能绕过首段验证。内核进程回收受操作系统行为限制，十秒是工作截止，不承诺内核阻塞时的总退出上限。

运行中的发布任务去掉 ENDLIST。FFmpeg 正常退出且最终结构校验通过后，最终清单、其摘要、分片数量、published 状态和任务 succeeded 在同一事务提交。任一步失败都保留之前的未结束版本；失败任务和失效执行租约不能继续读取。数据库发布失败会终止当前编码，并按执行租约恢复流程处理，不在失联状态下继续产出可见内容。

每次 GET、HEAD 和 Range 读取都对整份目标分片重新计算 SHA-256，并与持久化的长度/摘要匹配，然后使用同一个已检查句柄返回内容。即使只请求八个字节，也不能绕过整片验证。该方式增加磁盘读取量，暂不以大小/修改时间缓存来替代内容检查；持续负载与性能优化仍需测量。读租约在验证和响应期间保护缓存目录。

这些证明用于当前生成产物的完整性，版本 3 另有首段 FFmpeg 解码检查；它们不授予跨会话复用或 P2P 分享能力，也不等于整片或所有浏览器的解码保证。持有缓存卷写权限的外部程序仍可能在验证后原地改写同一文件；这里不承诺对恶意卷写入者的实时隔离。逐段可播放状态接口、旧代次独立回收及进程组故障验收仍待完成，W05 整包保持进行中。

验证入口：

- 隔离数据库示例 `verify_output_snapshots`：证明缺失/变化回滚、重复提交、旧完成 API 不可绕过、owner/租约/停止会话隔离、等待锁后租约过期、最终提交故障回滚和级联清理。
- `tests/worker-attempts.mjs`：已提交清单不受私有清单半写影响；等长载荷损坏和证明缺失导致 GET/HEAD/Range 拒绝。版本 1 的读取兼容场景继续保留。
- `tests/worker-processes.mjs`：真实 FFmpeg 运行期间核对分片摘要及可见清单；模拟私有清单重写时继续读取上一版；正常完成后的 HTTP 清单完整解码及进程故障回归。
