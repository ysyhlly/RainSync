# 写入空间预留

迁移 `0013_cache_write_reservations.sql` 增加一个共享预算版本和按 job/owner/attempt 绑定的预留。使用同一数据库的 Worker 必须共享缓存卷及额度配置；此版本不是不同缓存盘之间的调度器。升级顺序同 CACHE_LEASES.md，禁止旧 Worker 绕过预算并行编码。

Server 在创建本地 HLS 任务时保存预计输出字节数：剩余秒数 × 估计总码率 ÷ 8 × 1.15。转封装优先使用探测的源总码率；缺失码率及 CRF 视频转码使用 8 Mbit/s 视频估计，另加 192 kbit/s 音频余量，最少 64 KiB。CRF 不是固定码率，这只是容量准入估计，不能承诺真实文件一定小于该值。未知时长及旧任务使用 `CACHE_UNKNOWN_OUTPUT_BYTES`，默认 2 GiB。

Worker 启动 FFmpeg 前，先清理可淘汰缓存，再读取预算版本，在事务外测量磁盘与缓存大小。短事务锁定预算行，确认版本未改变、任务 owner/attempt/租期及播放会话仍有效，然后检查可用空间扣除所有现有预留后是否足够。任何预留或释放都会增加版本；测量期间有人释放预算时，旧测量不能遗漏刚完成的文件，必须重新测量。并发变化最多重试四次，仍不稳定交由任务租约恢复。

默认缓存上限 20 GiB，同时保持磁盘总容量 10% 的余量。预留不足时尝试淘汰可回收目录后重新申请；单个预计输出本身就超过额度时直接失败，不为了不可能满足的申请清空缓存。容量不足沿用 `CACHE_CAPACITY_EXCEEDED`。Compose 和 `.env.example` 已暴露两个字节额度配置。

目前采取保守记账：运行期间既计入实际缓存大小，也保留整笔输出预留，直到编码子进程已回收。这样可能比剩余输出的精细记账更早拒绝新任务，但不会因为使用一个较旧的扫描结果先释放预算而漏计已完成输出。后续可以用一致的磁盘计量代次优化重复计费，不能直接将异步测得的单任务大小从预留中扣除。

正常完成、失败、取消和退出统一在子进程回收后释放。取消状态本身不会提前清空仍有有效执行租约的预算。数据库不可用时保留记录，下次预算快照按消失任务、owner/attempt 变化或租约到期回收并增加版本。预留表不使用任务级联删除，避免静默释放绕过版本检查。

实际磁盘占用仍在编码期间和完成时检查；预估不足或其他进程填满磁盘仍可能导致 ENOSPC，不能用“已预留”跳过失败处理。验证包括真实数据库并发申请/陈旧测量/过期回收，以及隔离小卷上的超额拒绝、先淘汰再准入、准备失败释放、SIGTERM 释放和故意低估后的实际写满。

另有独立 Linux tmpfs 场景：只读挂载，以及 UID 10001 可读但不可写的 0500 目录。先用同一容器用户的实际写操作确认分别为 EROFS/权限拒绝，再检查任务失败、没有可见清单、无残留预留和 FFmpeg、Worker 仍可正常关闭。预留估计降为 64 KiB，避免把容量不足误当访问故障。两项可能在编码启动前失败，不代表编码中途撤掉权限或只读文件系统的恢复能力。

创建缓存输出目录时，按操作系统错误类型记录只读、权限拒绝和空间耗尽，分别公开为 `CACHE_READ_ONLY`、`CACHE_PERMISSION_DENIED` 和 `CACHE_CAPACITY_EXCEEDED`。这些已终止任务的错误不可通过重试其播放 URL 恢复，需修复环境后重新准备。分类只应用于缓存写入点，不能把源读取或 FFmpeg 启动权限错误误报为缓存权限。编码过程中 FFmpeg 的泛化退出失败仍为 `MEDIA_JOB_FAILED`，没有靠匹配原始 stderr 猜测原因。
