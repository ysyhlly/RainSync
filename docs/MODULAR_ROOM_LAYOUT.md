# 我的放映室布局

放映室可以按自己的习惯摆放组件。默认桌面布局为左侧大画面、右侧聊天、画面下方影片详情与紧凑待播列表、右下方在线成员。米色界面、原有字体和图标沿用现有应用；桌面房间页使用横向导航，其余页面保持原有导航。

## 编辑与保存

1. 选择“编辑布局”进入编辑模式。观看模式不显示网格和拖动把手。
2. 使用组件左上角把手移动，右下角把手调整尺寸。播放器按宽度等比调整，视频使用包含式适配，不裁切或拉伸画面。
3. “添加组件”列出房间信息、播放器、影片详情、聊天、待播和在线成员。每种组件只能有一个；已添加的组件可直接定位。
4. 可隐藏非播放器组件，之后从目录添加回来。隐藏不会删除聊天、待播影片或成员，也不会改变别人的布局。播放器是必要组件，不能隐藏。
5. “撤销”和“重做”处理本次编辑的历史；“取消”恢复进入编辑前的布局；“完成”保存并锁定布局。恢复默认也属于草稿操作，选择“完成”才保存，选择“取消”可放弃。

“房间管理”、离开、选片、邀请和必要错误提示在可隐藏组件之外，是否可用仍由原有权限与房间状态决定。

## 键盘和触摸

- Tab 可依次到达编辑按钮、组件把手、调整按钮与业务控件，焦点有明显轮廓
- 聚焦移动把手后，使用方向键移动；宽屏按住 Shift 可加大步幅
- 聚焦调整大小的把手后，用方向键调整；播放器保持比例
- 组件的“调整位置和大小”按钮提供可点击的方向与尺寸按钮，无需拖拽
- 拖动时按 Escape 取消当前手势；顶部“取消”放弃整个编辑草稿
- 触摸从专用把手开始；普通聊天与列表区域仍可滚动
- 窄屏按单列顺序显示，移动使用上、下方向或对应按钮；播放器随可用宽度保持比例

不会覆盖聊天输入框的普通文字编辑按键。系统开启减少动态效果时，布局不使用位移过渡或动画。

## 保存范围与隐私

布局仅保存到当前浏览器的本地存储，按当前账号和宽屏／窄屏分别隔离，不向房间内其他人同步。它是这个账号的放映室偏好，不是每个房间单独一份。不同浏览器、设备或浏览器配置不会自动共享；清除网站数据后需要重新设置。未登录状态不写入账号布局。

仅保存组件类型、标识和网格坐标／尺寸，不保存账号凭据、会话、聊天正文、影片资料、播放地址或成员数据。读取损坏、不合法或无法识别版本的记录时使用默认布局并提示，不在读取时覆盖原记录。遇到更新版本的记录，需要明确恢复默认后再保存才能替换。

保存失败会保留编辑草稿和原有已保存布局，可以重试或取消；不能把失败提示当作已保存。切换账号或宽窄屏布局范围时会结束旧范围的编辑草稿，开始调整前应先完成或取消。

## 本批范围和边界

- 宽屏使用 24 列网格；根据放映室实际可用宽度切换到单列窄屏，阈值由布局模型统一管理
- 位置、尺寸、边界、重叠、组件单例及必要播放器均受校验；不可放置的位置会提示且保留原位置
- 各组件有最小尺寸，长内容在组件内部滚动；文字与播放器控件同时根据组件自身宽度适配
- 播放器保持在应用层的同一个实例，布局仅更新其位置；不因摆放组件主动重建视频元素或重新请求播放
- 本批不包括云同步、多人共享布局、便签、投票、组件市场和任意第三方组件
- 页面缩放、浏览器存储限制、媒体与平台播放能力仍受原有应用和浏览器约束

## 实现与验证入口

- `apps/web/src/features/room-layout/`：布局模型、几何运算、本地存储、编辑控制与组件画布
- `apps/web/src/styles/room-layout.css`：房间限定的外观、组件宽度适配、编辑层级、焦点与减少动态效果
- `apps/web/src/main.ts`：在原有样式之后引入房间布局样式
- `tests/room-layout-model.test.ts`、`tests/room-layout-state.test.ts`：几何与保存事务的单元测试
- `tests/browser/room-layout.spec.ts`：房间布局浏览器测试

上述为测试入口，不是测试通过声明。构建、单元测试、实际浏览器交互和视觉检查应分别报告；仅构建成功不能证明布局视觉或播放连续性已验收。该功能不修改后端协议、数据库或媒体处理实现。
