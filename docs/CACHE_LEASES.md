# 缓存读取与清理互斥

迁移 `0012_cache_read_leases.sql` 增量扩展原有 cache_entries，保留旧键和路径，给可识别的 UUID 缓存键回填 id。新增读取租约表。文件删除仍只使用缓存根目录下由服务端 UUID 构造的目录，不使用数据库里保存的任意 path。

当前使用同一数据库的 Worker 应共享同一缓存卷。升级时先停止旧 Worker，运行 Server 迁移，再启动新版 Worker；旧 Worker 不识别读租约，不能与新版清理逻辑混跑。

Worker 读取本地生成的清单、初始化段或分片前取得租约；源文件直放不属于可淘汰缓存，不登记到此表。读取准入与淘汰均锁同一个 cache_entries 行。淘汰必须确认没有活跃播放会话、有效运行任务或有效读取租约，先提交 evicting 和清理者编号，之后才在事务外删除目录。新读取无法进入 evicting/evicted。删除失败保留 evicting，三十秒清理者租期结束后可接手；旧清理者不能完成新清理者的记录。

读取租期三十秒，每五秒在独立任务中续期，数据库操作最多等待三秒。客户端背压不暂停续期。响应结束、取消或错误会释放租约；进程崩溃由租期回收。流在每次交付字节前检查本地续期时间，超过二十五秒或续期失败即中断，避免暂停过久的进程恢复后继续交付。播放会话停止或过期会拒绝续期。已经送入操作系统/客户端缓冲区的字节无法收回。

容量压力下按真实读取更新的 last_used 排序，逐个申请淘汰，而不是使用早先取得的“活跃会话”快照直接删目录。已打开文件在 Windows 上可能阻止删除；此时保留淘汰状态并等待重试，不依赖 Unix 的打开后删除语义。统计遇到其他清理者刚删除的目录/文件按零计量，权限等其他错误仍保留。

若进程在删完目录、写回数据库之前中断，下一轮容量维护即使没有空间压力，也会重试过期的 evicting 记录；目录已经不存在同样可以完成收尾。完成提交要求清理者编号和未过期租期同时匹配，并清除该目录的残留读租约。普通元数据维护每轮分别最多清理 1000 条过期读租约及淘汰记录；淘汰记录至少保留 48 小时，且原播放会话和任务都已删除后才能移除。

验证入口：`cargo build --workspace --bins --examples --locked` 后运行 `node tests/integration.mjs`，以及独立镜像的 `node tests/worker-processes.mjs`。

- 真实 PostgreSQL 验证多个读者、停止后保护、过期不能续活、并发淘汰单一获胜及旧清理者隔离。
- 真实 Worker 的 100 MiB 文件暂停 HTTP 消费六秒，确认租约仍续期；使租约失效后确认传输中断。
- 隔离缓存卷同时放置有租约和空闲目录，低配额触发实际淘汰，只删除空闲目录；模拟崩溃读者租期结束后才删除受保护目录。
